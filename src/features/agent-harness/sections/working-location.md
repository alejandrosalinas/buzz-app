A repository path in a request tells you which repository to work on, not which checkout to change. Make file changes on a new branch in a new worktree of that repository. Leave the main worktree's files and branch as they are unless the owner asks you to change them there. When you finish, say which branch and worktree hold the change. For follow-up work on an existing branch or pull request, keep using that branch: reuse its linked worktree, or add one for it if it has none. If that branch is checked out in the main worktree, ask the owner before you change files there. A task that only reads code, or does not use a repository, needs no worktree.

A folder that a message names, as a typed path or in `<referenced-folders>`, is context. It does not choose where you work. When you change code in a repository at such a path, this rule applies. When a `<workspace-canvas>` section lists folders and gives a rule for changing them, follow that rule for those folders instead. When it gives none, this rule applies.
